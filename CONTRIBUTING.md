# Contributing to PhisingSim

Thank you for your interest in contributing to PhisingSim! As a security training simulator, it is crucial that all contributions maintain high code quality and adhere strictly to ethical guidelines.

---

## Ethical Standards

By contributing to this repository, you agree that:
1. **No Exploit Code**: You will not submit code designed to bypass active security controls, exploit unpatched vulnerabilities, or facilitate illegal cyberattacks.
2. **Simulation Focus**: All templates and features must serve the purpose of simulating phishing and raising user awareness.
3. **No Malicious Features**: Features like automatic payload delivery, active malware execution, or credentials exfiltration to unauthorized third-party services are strictly prohibited.

---

## How Can I Contribute?

### 1. Reporting Bugs
- Search existing issues to ensure the bug hasn't been reported yet.
- If it's a new issue, open a standard bug report on GitHub.
- Provide a clear summary, steps to reproduce, and screenshots if applicable.
- **Do not report security vulnerabilities via public issues** (see [SECURITY.md](file:///c:/xampp/htdocs/PhisingSim/SECURITY.md)).

### 2. Suggesting Enhancements
- Open a feature request issue on GitHub.
- Clearly describe the feature, the use case, and how it benefits security awareness training.

### 3. Submitting Pull Requests
Follow this workflow to submit code changes:

1. **Fork the Repository**: Create your own copy of the repository.
2. **Clone Locally**: 
   ```bash
   git clone https://github.com/your-username/PhisingSim.git
   cd PhisingSim
   ```
3. **Create a Branch**: Create a descriptive branch name.
   ```bash
   git checkout -b feature/add-new-simulation-template
   ```
4. **Follow Coding Standards**:
   - Follow standard Laravel and PSR-12 coding practices for PHP.
   - Use clean, well-commented code.
   - Write/update tests if applicable.
5. **Commit Your Changes**: Make clear, descriptive commit messages.
   ```bash
   git commit -m "Add LinkedIn phishing simulation template"
   ```
6. **Push to Your Fork**:
   ```bash
   git push origin feature/add-new-simulation-template
   ```
7. **Submit a Pull Request**: Open a PR from your branch to the main PhisingSim repository. Describe your changes clearly and link any related issues.

## Code of Conduct

We expect all contributors to maintain a respectful, welcoming, and collaborative environment. Please be professional and constructive in all communication.
